## Запрос от браузера до базы

React Router открывает страницы из `frontend/src/pages`. Общий Layout содержит навигацию и AssistantDock; сессия загружается через auth-контекст. `useApi` получает JSON с `/api`. В разработке Vite на 5173 проксирует API на Flask 5000. После сборки Flask раздаёт `frontend/dist` и API с одного origin. MongoDB доступна только серверу.

`backend/app.py` создаёт Flask, подключает маршруты, загружает текущего студента и добавляет защитные заголовки. `auth.py` проверяет scrypt-пароли и JWT-cookie. `api.py` валидирует вход, авторизацию и права владельца. `services.py` собирает расписание, оценки, сводку и уведомления; `serializers.py` переводит документы MongoDB в клиентский camelCase.

## Коллекции и изоляция

`users` хранит уникальный login, password_hash, учебный профиль и сценарий риска. `schedule` привязано к группе; `grades`, `requests` и `plan_tasks` — к user_id. `notifications` выбираются по аудитории; read_by хранит отметки конкретных пользователей. `counters` выдаёт номера заявок.

`db.py` создаёт индексы для логина, группы/дня/начала занятия, пользователя/семестра, пользователя/даты заявки, аудитории/даты уведомления. Уникальный составной multikey-индекс `(user_id, date, slot_ticks)` резервирует 15-минутные интервалы задач и препятствует параллельному бронированию одного времени.

`seed.py` — разрушительное пересоздание демо-базы. `demo_scenarios.py` дополняет отсутствующие истории идемпотентно. У Анны 5 семестров без долгов; у Максима 3 семестра, 11 долгов и 43% посещения. Это сценарные данные, а не аналитика реального университета.

## Планировщик

Окна вычисляются на 7 дней в пределах 09:00–18:00 по Москве. Сегодня начало округляется вперёд до 15 минут. Занятия, кроме отменённых, и личные задачи исключаются. Длительности: 30/45/60/90 минут. Перед записью сервер заново вычисляет доступность; устаревший выбор возвращает 409. Удалить задачу может только владелец.

## Внешний ИИ

Провайдеры используют OpenAI-совместимый `POST /chat/completions` с JSON-режимом. Режим `auto` при заданном `OPENROUTER_API_KEY` проходит цепочку `OPENROUTER_MODELS` и затем пробует публичный Pollinations; если OpenRouter не настроен, но есть `DEEPSEEK_API_KEY`, используется DeepSeek, затем Pollinations. Принудительный `deepseek`, `openrouter` или `pollinations` без ключа возвращает понятную ошибку 503. Ответ провайдера ограничен по размеру, базовые URL обязаны быть HTTPS.

Цепочка OpenRouter по умолчанию: `baidu/ernie-5.5-flash-preview:free`, `nvidia/nemotron-3.5-lightning:free`, `nvidia/nemotron-3-ultra-550b-a55b:free`, `openrouter/free`. Каждая попытка ограничена 30 секундами, вся цепочка — 70; для reasoning-моделей задан `reasoning.effort=low` и `max_tokens=4096`, иначе бесплатная модель тратит бюджет на скрытые рассуждения. Ошибка транспорта, обрезанный JSON или нарушение протокола ответа переводит к следующей модели. Pollinations ограничен 25 секундами; gunicorn и nginx допускают 100 секунд на запрос.

Контекст содержит учебные данные текущего демо-студента, его заявки, уведомления и личный план; пароли, cookie, чужие данные и личная переписка не отправляются. Ответ проверяется: текст, ограниченный список разрешённых действий и предложения задач. Ссылки строит сервер. ИИ не пишет в MongoDB и не отправляет заявления.

Основная публичная копия проходит цепочку бесплатных моделей OpenRouter и честно показывает `provider: OpenRouter` и `model`; при ошибке или лимите всех моделей `auto` возвращает `provider: Pollinations`. DeepSeek подключается ключом без правок кода. При ошибке UI сохраняет запрос и предлагает повторить; остальные разделы независимы от ИИ. Локальные браузерные тесты подменяют ответ провайдера.

## Эксплуатационные границы

Лимиты входа/помощника хранятся в памяти процесса; для нескольких экземпляров нужен общий ограничитель. Основная публичная копия работает по HTTPS на `campus.mxd.wtf` (443) с собственным `JWT_SECRET`, secure cookie и reverse proxy. Прежний адрес `finland.meowxd.net:8080` оставлен резервом. Доступность нового домена проверена напрямую; это не гарантирует каждого российского провайдера. Примеры конфигураций находятся в deploy/. Проверка в Chromium не заменяет реальные проверки Firefox/Safari.

## Подгрузка и стабильная геометрия

Страницы импортируются через React.lazy; Suspense внутри Layout сохраняет хедер и помощника при загрузке нового раздела. Аватар в хедере загружается сразу, второстепенные изображения используют native lazy loading. Тяжёлые шейдеры остаются отдельным ленивым модулем.

ScheduleRail подгружает недели в обе стороны через API расписания. В DOM остаётся до 5 недель; видимый день и его смещение сохраняются при добавлении и удалении краёв. Ошибка не удаляет уже загруженные дни, доступен повтор. API допускает относительную неделю от −5200 до +5200 (защитная граница примерно 100 лет в каждую сторону). Каждое обращение возвращает только расписание группы текущего пользователя.

ReactiveSurface разделяет неподвижный интерактивный элемент и двигающуюся поверхность. Клавиатурный фокус и hit testing относятся к внешнему элементу; фон, текст и декор двигаются вместе внутри. На панели с вложенными действиями сами действия сохраняют доступность. Reduced motion отключает перемещение. Общий средний балл отображается одной наклейкой вне сменяющегося семестрового содержимого.

## Социалка и стена

`backend/social.py` хранит посты (`social_posts`), сообщения (`social_messages`) и отметки чтения (`social_reads`). Отдельный blueprint наследует общую проверку сессии и Origin. Индексы поддерживают доступ по аудитории/группе, диалогу и ID; уникальный ключ сообщения `(channel, author_id, client_id)` обеспечивает идемпотентный повтор отправки. Демо-сообщения групп имеют `demo_key` и снимок автора `demo_author`, поэтому не требуют фиктивных логинов; сериализатор не доверяет произвольным полям. Публикации и сообщения ограничены rate-limit. Личные данные учебных разделов не копируются в социальные записи и не передаются ИИ.

`NewsWall.jsx` подгружает посты по курсору, держит окно до 60 записей и сохраняет позицию видимого поста при удалении верхнего края. Кнопка «К новым постам» возвращает первое окно. Форма публикации раскрывается по запросу; ввод остаётся после ошибки. Фикстура содержит 36 разных вымышленных постов. `seed_social_demo` обновляет только собственные помеченные демо-записи; пользовательские публикации сохраняются.

`Social.jsx` получает новые сообщения каждые 5 секунд при видимой вкладке, не допускает параллельных polling-запросов одного канала. История загружается явно по кнопке и сохраняется до ухода из диалога. Новые сообщения при чтении старой истории не отмечаются прочитанными: появляется переход вниз. Отправка сохраняет UUID при повторе и текст после ошибки. Для больших реальных архивов потребуется виртуализация истории; текущий прототип сохраняет вручную запрошенную историю открытого диалога.

Главный scroll-контейнер заканчивается перед выделенной полосой ИИ-помощника. Свёрнутый помощник не закрывает элементы контента. На мобильном личный контекст и чаты расположены перед стеной, учебные подробности раскрываются отдельно, поэтому бесконечная подгрузка постов не отодвигает их вниз.

## Дополнения финального прохода

`social_comments` хранит комментарии доступных студенту постов. Индекс `(post_id, author_id, client_id)` исключает дубли повтора UUID. Лайки сохраняются множеством ID внутри поста, наружу выдаются только количество и собственное состояние. Эти API сохранены из локальных изменений автора.

Помощник отклоняет ответ, если строка `answer` содержит протокольные поля `actionIds`/`tasks`: такая генерация не показывается студенту; режим auto использует существующий резерв. Поведение проверяется регрессиями, воспроизводящими обнаруженный публичный ответ.

В финальных исходниках `Layout` управляет нижним статичным кубом помощника и фокусом ввода. `AssistantDock` скрыт до открытия, сохраняет черновик/ответ при закрытии; Escape и крестик возвращают фокус на куб. Прежний мобильный триггер в шапке заменён этим общим входом на всех ширинах.
